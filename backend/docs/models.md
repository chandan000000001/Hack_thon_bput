# CYBERGUARD Models & Algorithms Details

CYBERGUARD's detection layer is a **transparent heuristic engine** (rule-based forensics, not a trained ML model). Every indicator is enumerable, every score is reproducible, and the LLM providers (Groq first, then OpenRouter, via `app/ai/llm_gateway.py`) are used **only** to write human-readable explanations — they never produce scores. Offline metrics for all modules live in [`evidence/reports/evaluation.md`](../../../evidence/reports/evaluation.md) (generated by `scripts/evaluate.py`).

## Scoring engine (shared by all modules)

`app/services/scoring_service.py`

- Each indicator carries a severity: **critical = 25**, **high = 15**, **medium = 5** points.
- `calculate_score(indicators)` sums weights, capped at 100.
- `get_severity(score)` maps to bands: **safe 0–20, low 21–40, medium 41–60, high 61–80, critical 81–100**.
- Alert pipeline: `risk_score = max(round(manipulation_probability * 100), indicator_score)` for media; pure indicator score elsewhere.

## Detection modules

| # | Module (code) | Purpose | Input | Key heuristic features | Scoring logic | OpenRouter role | Known limitations |
|---|---|---|---|---|---|---|---|
| 1 | **Phishing** (`app/services/phishing_detector.py`) | Detect phishing emails and SMS/social-engineering text | sender, subject, body | Leet-tolerant lookalike sender domains (paypa1, micr0soft → regex per brand, official-domain allowlist); urgency keywords; credential-request phrases; body URLs (IP hosts, plain HTTP, suspicious TLDs); threat language; **SMS layer:** 5–6 digit shortcodes, international/long phone numbers, spam vocabulary (txt, claim, winner, loan, cash, free, prize…), digit-to-letter ratio, 4+ consecutive ALL-CAPS words | Lookalike domain / credential request / malicious URL = critical (25); urgency / threat language / SMS keyword / shortcode / phone = high (15); digit ratio / ALL-CAPS = medium (5) | `PHISHING_SYSTEM_PROMPT` — explanation paragraph starting with the risk level, MITRE techniques (e.g. T1566.001), recommended actions | Vocabulary-based; novel lures without listed markers score lower; sender-domain allowlist is a fixed brand list |
| 2 | **Malicious URL** (`app/services/url_detector.py`) | Detect malicious, spoofed or malware-distribution URLs | single URL string | IP-based host; URL length > 75 and Shannon entropy > 4.0; suspicious TLDs (.xyz/.top/.zip/…); brand name in subdomain; plain HTTP; credential path keywords; **URLhaus tuning:** executable/payload extensions (.exe/.php/.js/.vbs/.hta/.ppc/.mips/…), random high-entropy path segments, excessive digit ratio in host+path, abused-TLD + long-path pattern | IP host / brand-in-subdomain = critical (25); executable extension, suspicious TLD, HTTP, URLhaus pattern = high (15); length, entropy, random segment, digit ratio, path keywords = medium (5) | `URL_SYSTEM_PROMPT` — lexical/redirect-focused explanation (T1566.002) | Point-in-time lexical rules; compromised *legitimate* domains with clean paths can pass; no DNS reputation or live page fetching |
| 3 | **Impersonation** (`app/services/impersonation_detector.py`) | Detect CEO-fraud / BEC and authority impersonation | message text + claimed identity | Authority keywords in claimed identity (CEO, CFO, director, principal, bank, IRS, IT support; acronyms matched on word boundaries, full titles included); pressure phrases (urgent, immediately, do not question, confidential, ASAP); unusual financial requests (gift card, wire transfer, bitcoin, bypass procedure, share codes) = critical; secrecy phrases (don't tell anyone, keep this between us) | Authority identity / pressure / secrecy = high (15); unusual request = critical (25) | `IMPERSONATION_SYSTEM_PROMPT` (T1656) | English-only phrase lists; a skilled impersonator avoiding listed phrases scores lower; no sender-history profiling yet |
| 4 | **Account takeover** (`app/services/account_takeover_detector.py`) | Detect credential stuffing, brute force and hijacked sessions | list of auth events (`user`, `ip`, `location`, `device`, `status`, `timestamp`) | Failed-login burst (≥ 3 failures per user); impossible travel (successful logins from different locations < 60 min apart); new/unknown device (first device per user in batch is the baseline); suspicious device agents (Linux/unknown); success immediately after ≥ 2 consecutive failures | Impossible travel = critical (25); burst / success-after-failures = high (15); new or unknown device = medium (5) | `ACCOUNT_TAKEOVER_SYSTEM_PROMPT` (T1110.003) | Batch-local baselines (no long-term user history); timestamp parsing depends on ISO-8601 input; location strings compared literally |
| 5 | **Network / API abuse** (`app/services/network_threat_detector.py`) | Detect exfiltration, C2 channels and API abuse | flows (`source_ip`, `dest_ip`, `port`, `bytes_out`, `protocol`) + API logs (`endpoint`, `method`, `source_ip`, `status_code`) | Outbound volume > 10 MB per flow; C2/backdoor ports (4444, 8888, 1337, 31337, 6667); > 50 requests from one source IP; > 5 HTTP 401s from one source IP | C2 port = critical (25); exfiltration, rate abuse, repeated auth failures = high (15) | `NETWORK_THREAT_SYSTEM_PROMPT` (T1041) | Fixed thresholds; no flow temporal baselining or per-tenant traffic profiles; beaconing checked only implicitly via repeated identical flows |
| 6 | **Deepfake / media forensics** (`app/services/deepfake_detector.py` + `app/services/media_forensics/`) | Detect manipulated images/videos and synthetic audio indicators | media bytes (image, video, audio ≤ 25 MB) | **Images: Error Level Analysis (ELA)** via Pillow — JPEG q90 re-encode, per-pixel residual mean/max and 8×8 block variance (splicing), uniform-error maps, missing EXIF, container mismatch. **Videos:** ≤ 10 sampled frames (OpenCV) + per-frame ELA + temporal ELA variance + container sanity (fps, frame count). **WAV audio:** real signal statistics (clipping ratio, zero-crossing-rate variance, spectral flatness proxy / spectral holes via numpy FFT). **Non-WAV audio: SIMULATED** — deterministic SHA-256-derived score with `simulated: true` and a reserved Hugging Face model hook | `manipulation_probability` from the analyzer combined with indicator score; final `risk_score = max(round(prob * 100), indicator_score)`; response always carries `method` and `simulated` flags | `DEEPFAKE_SYSTEM_PROMPT` — must include "Flag multimedia for manual verification" when `manipulation_probability > 0.5` | ELA is a **manipulation-forensics heuristic, not an ML deepfake model** — calibrated on synthetic gradient images and weak against whole-image regeneration; video sampling covers ≤ 10 frames; non-WAV audio results are explicitly simulated; no face/identity or lip-sync analysis |

## Media forensics interface

All media analyzers implement one abstract interface (`app/services/media_forensics/base.py`):

```python
class MediaAnalyzer(ABC):
    def analyze(self, file_bytes: bytes, file_name: str) -> dict:
        # -> authenticity_score (0-1), manipulation_probability (0-1),
        #    indicators (list), method (str), simulated (bool)
```

This contract exists so a Hugging Face vision/audio model can be dropped in later **without any API change**: `ImageAnalyzer`, `VideoAnalyzer` and `AudioAnalyzer` are interchangeable in `deepfake_detector.analyze_media`.

## Explainable AI layer

`app/ai/openrouter_client.py` + `app/ai/prompt_templates.py`

- One shared async `call_openrouter(system_prompt, user_prompt)` — JSON response mode, per-call timeout from `OPENROUTER_TIMEOUT_SECONDS` (default 60 s, enforced across the gateway chain), headers identify the app (`HTTP-Referer`, `X-Title: CYBERGUARD`).
- Every failure path (missing key, timeout, HTTP error, unparseable output — with a regex JSON-block extractor for markdown-fenced replies) returns a fixed fallback explanation, so detection and alerting never depend on the LLM.
- Per-module system prompts constrain the model to a strict JSON contract (`explanation`, `mitre_techniques`, `recommended_actions`); the SOC assistant prompt grounds answers in the last 20 alerts and cites alert IDs.
- Model: `OPENROUTER_MODEL` (default `meta-llama/llama-3.1-8b-instruct:free`).

## Trained model cards (ML Step 3 — Hybrid Detection Engine)

Since ML Step 3 the detection pipeline is **hybrid**: the heuristic indicators above are combined with trained models served from `ml/models/` via `app/services/ml_inference.py`. The blend applied consistently by all ML-backed detectors is:

```
hybrid_score = round(0.45 * heuristic_score + 0.55 * ml_probability * 100)
```

When `ML_ENABLED=false` (or a model file is missing), the predictors return `None`, no `ml_model` indicator is appended, and behaviour is identical to the pre-integration heuristic pipeline.

### 1. Email phishing — `email_phishing_xgb.pkl` + `email_tfidf.pkl`

- **Algorithm:** TF-IDF (max_features 50,000, English stop words) → XGBoost classifier.
- **Dataset:** Hugging Face `cybersectony/PhishingEmailDetectionv2.0` (120,000 emails; the spec'd primary `pirocheto/phishing-email` is gated on the Hub and was skipped). 80/20 split → 95,996 train / 24,000 held-out test. Labels: 0 benign, 1 phishing/fraud.
- **Imbalance handling:** dataset is ~94% phishing; `scale_pos_weight = count(benign)/count(phishing)` ≈ 0.06 on the sampled training set.
- **Held-out test metrics:** accuracy 0.9813, precision 0.9995, recall 0.9807, **F1 0.9900**.
- **Blending:** 0.45 heuristic / 0.55 ML (`predict_email` on sender + subject + body).
- **Limitations:** trained on one public email distribution — marketing-style ham and non-English phishing are under-represented; the gated primary dataset was not used.

### 2. URL malicious — `url_xgb.pkl`

- **Algorithm:** XGBoost over 8 handcrafted features (`extract_url_features`: length, Shannon entropy, digit ratio, has_ip, has_at_symbol, suspicious TLD, http-only, subdomain count).
- **Dataset:** Part 8 URL datasets (500 URLhaus malicious + 500 Umbrella benign), 80/20 split → 800 train / **200 held-out test**.
- **Held-out test metrics:** accuracy 1.0000, precision 1.0000, recall 1.0000, **F1 1.0000**.
- **Blending:** 0.45 heuristic / 0.55 ML (`predict_url`).
- **Limitations:** ⚠️ **small-sample caveat** — a perfect F1 on 200 held-out rows reflects the narrow, easily separable feature set and does not predict real-world performance; expect degradation on novel phishing infrastructure.

### 3. Deepfake image CNN — `deepfake_cnn.pt`

- **Algorithm:** PyTorch CNN (Conv 3→16→32 + MaxPool, FC 8192→64→2), 136,354 parameters, trained 2 epochs (Adam, CrossEntropyLoss) on 32×32 images.
- **Dataset:** CIFAKE (via accessible mirror `dragonintelligence/CIFAKE-image-dataset`, train split, 100,000 images; 80/20 split → 80,000 train / 20,000 held-out test). Labels: real (CIFAR-10 photos) vs fake (AI-generated).
- **Held-out test metrics:** accuracy 0.9156, precision 0.9122, recall 0.9197, **F1 0.9159**.
- **Blending:** for images `manipulation_probability = 0.5 * ELA + 0.5 * CNN`; for videos the CNN is averaged over ≤ 5 sampled frames and blended with the ELA temporal score. `simulated` stays `false`.
- **Limitations:** ⚠️ **CIFAKE images are 32×32** — resolution is far below real-world media, so metrics do not transfer to high-resolution photos; ELA+CNN blend reduced the heuristic-only false-positive rate on this dataset from 1.000 to 0.058 but recall dropped from 1.000 to 0.898.

### 4. Network anomaly — `network_xgb.pkl` (+ `network_scaler.pkl`)

- **Algorithm:** XGBoost over the 4 scaled KDD99 "SF" features (log-duration, label-encoded service, log-src_bytes, log-dst_bytes; scaler persisted via joblib at preprocessing time).
- **Dataset:** `sklearn.datasets.fetch_kddcup99(subset="SF")` — 73,237 flows; binary target (normal vs any attack); 80/20 split → 58,589 train / 14,648 held-out test.
- **Held-out test metrics:** accuracy 0.9995, precision 0.9952, recall 0.9936, **F1 0.9944**.
- **Blending:** 0.45 heuristic / 0.55 ML; each flow dict is mapped to the training features with documented derivations (duration and response bytes are unavailable in our flow schema and use the log-floor constant ln(0.1); service is derived from the destination port, unknown ports → KDD's `other`).
- **Limitations:** ⚠️ **KDD99 is 1998 DARPA evaluation data** — decades-old attack patterns that barely overlap modern traffic; on the synthetic network scenarios the hybrid blend *reduced* recall to 0.0 (the model scores our scenario flows as benign), which is reported honestly in `evidence/reports/evaluation.md`. No trained audio model exists — deepfake audio remains heuristic (WAV) or simulated (non-WAV).

## Explanation provider chain

Analysis explanations (phishing, URL, impersonation, deepfake, account
takeover, network/API) are produced by `app/ai/llm_gateway.py`, which tries
providers strictly in order and returns as soon as one succeeds:

| # | Provider | Timeout | Notes |
|---|----------|---------|-------|
| 1 | Groq | `GROQ_TIMEOUT_SECONDS` (default 20 s) | OpenAI-compatible `api.groq.com` endpoint, model `GROQ_MODEL` (default `llama-3.1-8b-instant`); skipped instantly when `GROQ_API_KEY` is empty |
| 2 | OpenRouter | `OPENROUTER_TIMEOUT_SECONDS` (default 60 s) | strict-JSON instruction, unchanged headers/parsing |
| 3 | rule_based | instant (< 5 ms) | template-generated locally from the indicator list already present in the prompt context when both remote providers fail; never fails |

- **Circuit breakers (Phase C-1):** each remote provider sits behind its own
  `AsyncCircuitBreaker` (`app/ai/async_circuit_breaker.py`; threshold 3
  consecutive failures, 60 s recovery window, CLOSED/OPEN/HALF_OPEN states).
  While a breaker is OPEN the gateway logs
  `Circuit breaker OPEN for <provider>, skipping to fallback` and moves to the
  next provider **instantly** — a sustained LLM outage costs near-zero added
  latency instead of the full timeout chain.
- **Provenance:** every analysis response carries `explanation_provider`
  (`openrouter` | `groq` | `rule_based` | `cache:<original_provider>`) and
  `explanation_latency_ms`. Each provider failure logs one warning line:
  `LLM provider <name> failed after <ms> ms: <reason>`.
- **Cache:** successful explanations are cached in-memory for 3600 s (max 256
  entries, thread-safe LRU) keyed by sha256 of module name + normalized input
  (for media: sha256 of the file bytes). Cache hits return with
  `explanation_provider = "cache:<original_provider>"` and zero latency.
- **Worst-case latency bound:** 20 s (Groq) + 60 s (OpenRouter) + < 1 s
  (rule_based) per analysis while providers are healthy; typically far less,
  zero on cache hits, and near-zero once a breaker has tripped.
- Detection heuristics, ML models, scoring bands and route signatures are
  unchanged by this chain — only the explanation source is affected.

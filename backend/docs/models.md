# CYBERGUARD Models & Algorithms Details

CYBERGUARD's detection layer is **hybrid**: transparent heuristic engines (every indicator enumerable, every score reproducible) combined with **five trained models** served from `ml/models/` via `app/services/ml_inference.py`. The LLM providers (Groq first, then OpenRouter, via `app/ai/llm_gateway.py`) are used **only** to write human-readable explanations — they never produce scores. Offline metrics live in [`evidence/reports/evaluation.md`](../../../evidence/reports/evaluation.md) (generated by `scripts/evaluate.py`; generated 2026-09-07).

## Scoring engine (shared by all modules)

`app/services/scoring_service.py`

- Each heuristic indicator carries a severity: **critical = 25**, **high = 15**, **medium = 5** points.
- `calculate_score(indicators)` sums weights, capped at 100.
- `get_severity(score)` maps to bands: **safe 0–20, low 21–40, medium 41–60, high 61–80, critical 81–100**.
- Heuristic modules are **flagged** at `risk_score >= 41` in the evaluation harness; media forensics is flagged at `manipulation_probability >= 0.5`.

## Hybrid blending rule (all ML-backed detectors)

```
hybrid_score = max(heuristic_score, round(0.45 * heuristic_score + 0.55 * ml_probability * 100))
```

- **Monotonic / safety principle:** a trained model may raise a score but may **never lower it below the heuristic verdict** — a strong heuristic signal (e.g. a C2-port exfiltration event) cannot be diluted by a weak or mismatched ML signal.
- The ML contribution is appended as a `type: "ml_model"` indicator carrying the numeric probability; `split_ml_indicator()` separates it out so it never adds heuristic weight.
- When `ML_ENABLED=false` or a model file is missing, predictors return `None`, no `ml_model` indicator is appended, and behaviour is byte-identical to the heuristics-only pipeline.

## Heuristic engine cards

### 1. Phishing — `app/services/phishing_detector.py`

- **Input:** sender, subject, body. **Output:** indicators + heuristic score.
- **Key heuristics:** leet-tolerant lookalike sender domains (paypa1, micr0soft → per-brand regex with an official-domain allowlist); urgency keywords; credential-request phrases; body URLs (IP hosts, plain HTTP, suspicious TLDs); threat language; SMS layer: 5–6 digit shortcodes, international/long phone numbers, spam vocabulary (txt, claim, winner, loan, cash, free, prize…), digit-to-letter ratio, 4+ consecutive ALL-CAPS words.
- **Weights:** lookalike domain / credential request / malicious URL = critical (25); urgency / threat language / SMS keyword / shortcode / phone = high (15); digit ratio / ALL-CAPS = medium (5).
- **Limitations:** vocabulary-based; novel lures without listed markers score lower; fixed brand allowlist.

### 2. Malicious URL — `app/services/url_detector.py`

- **Input:** single URL string.
- **Key heuristics:** IP-based host; URL length > 75 with Shannon entropy > 4.0; suspicious TLDs (.xyz/.top/.zip/…); brand name in subdomain; plain HTTP; credential path keywords; URLhaus tuning: executable/payload extensions (.exe/.php/.js/.vbs/.hta/…), random high-entropy path segments, excessive digit ratio, abused-TLD + long-path pattern.
- **Weights:** IP host / brand-in-subdomain = critical (25); executable extension, suspicious TLD, HTTP, URLhaus pattern = high (15); length, entropy, random segment, digit ratio, path keywords = medium (5).
- **Limitations:** point-in-time lexical rules; compromised *legitimate* domains with clean paths can pass; no DNS reputation or live page fetching.

### 3. Impersonation — `app/services/impersonation_detector.py`

- **Input:** message text + claimed identity.
- **Key heuristics:** authority keywords in the claimed identity (CEO, CFO, director, principal, bank, IRS, IT support — acronyms matched on word boundaries); pressure phrases (urgent, immediately, do not question, confidential, ASAP); unusual financial requests (gift card, wire transfer, bitcoin, bypass procedure, share codes); secrecy phrases (don't tell anyone, keep this between us).
- **Weights:** authority identity / pressure / secrecy = high (15); unusual request = critical (25).
- **Limitations:** English-only phrase lists; a skilled impersonator avoiding listed phrases scores lower; no sender-history profiling.

### 4. Account takeover — `app/services/account_takeover_detector.py`

- **Input:** list of auth events (`user`, `ip`, `location`, `device`, `status`, `timestamp` — ISO-8601 timestamps).
- **Key heuristics:** failed-login burst (≥ 3 failures per user); impossible travel (successful logins from different locations < 60 min apart); new/unknown device (first device per user in the batch is the baseline); suspicious device agents; success immediately after ≥ 2 consecutive failures.
- **Weights:** impossible travel = critical (25); burst / success-after-failures = high (15); new or unknown device = medium (5).
- **Limitations:** batch-local baselines (no long-term user history); ISO-8601 timestamps only; literal location-string comparison.

### 5. Network / API abuse — `app/services/network_threat_detector.py`

- **Input:** flows (`source_ip`, `dest_ip`, `port`, `bytes_out`, `protocol`) and/or API logs (`endpoint`, `method`, `source_ip`, `status_code`). Module `network` when flows are present, else `api_abuse`.
- **Key heuristics:** outbound volume > 10 MB per flow; C2/backdoor ports (4444, 8888, 1337, 31337, 6667); > 50 requests from one source IP; > 5 HTTP 401s from one source IP.
- **Weights:** C2 port = critical (25); exfiltration, rate abuse, repeated auth failures = high (15).
- **Limitations:** fixed thresholds; no temporal baselining or per-tenant traffic profiles; beaconing detected only implicitly via repeated identical flows.

### 6. Deepfake / media forensics — `app/services/deepfake_detector.py` + `app/services/media_forensics/`

- **Input:** media bytes (image, video, audio ≤ 25 MB).
- **Images:** Error Level Analysis (ELA) via Pillow — JPEG q90 re-encode, per-pixel residual mean/max and 8×8 block variance (splicing), uniform-error maps, missing EXIF, container mismatch.
- **Videos:** ≤ 10 sampled frames (OpenCV) + per-frame ELA + temporal ELA variance + container sanity (fps, frame count).
- **WAV audio:** real signal statistics (clipping ratio, zero-crossing-rate variance, spectral flatness proxy / spectral holes via numpy FFT).
- **Non-WAV audio: SIMULATED** — deterministic SHA-256-derived score returned with `simulated: true` and a **reserved Hugging Face model hook** in `media_forensics/base.py` so a real audio anti-spoofing model can drop in without any API change.
- **Scoring:** `risk_score = max(round(manipulation_probability × 100), indicator_score)`; flagged at `manipulation_probability >= 0.5`; the response always carries `method` and `simulated` flags.
- **Limitations:** ELA is a manipulation-forensics heuristic, not a deepface/lip-sync model — calibrated on synthetic gradient images and weak against whole-image regeneration; video sampling covers ≤ 10 frames; non-WAV audio results are explicitly simulated; no face/identity or lip-sync analysis.

All media analyzers implement one abstract interface (`app/services/media_forensics/base.py`): `analyze(file_bytes, file_name) -> {authenticity_score, manipulation_probability, indicators, method, simulated}` — `ImageAnalyzer`, `VideoAnalyzer` and `AudioAnalyzer` are interchangeable in `deepfake_detector.analyze_media`.

## Trained model cards

Artifacts live in `backend/ml/models/`; SHA-256 hashes are recorded in [`evidence/reports/evaluation.md`](../../../evidence/reports/evaluation.md). Training metrics below come from the training pipeline (`ml/train_models.py`, held-out splits produced by `ml/preprocess.py`); detection-level metrics come from `scripts/evaluate.py`.

### 1. Email phishing — `email_phishing_xgb.pkl` + `email_tfidf.pkl`

- **Algorithm:** TF-IDF (max_features 50,000, English stop words) → XGBoost classifier.
- **Dataset:** Hugging Face `cybersectony/PhishingEmailDetectionv2.0` (232,809 raw emails → 120,000 sampled; the spec'd primary `pirocheto/phishing-email` is gated on the Hub and was skipped). 80/20 split → **95,996 train / 24,000 held-out test** (verified on disk). Labels: 0 benign, 1 phishing/fraud; ~94% phishing, balanced with `scale_pos_weight = count(benign)/count(phishing)` ≈ 0.06.
- **Training metrics:** accuracy 0.9813, precision 0.9995, recall 0.9807, F1 0.9900.
- **Detection metrics (evaluation report, hybrid, n=24000):** accuracy 0.9705, precision 0.9929, recall 0.9756, **F1 0.9842** (heuristics-only F1: 0.0268). Mean 2.278 ms / P95 8.07 ms.
- **Blending:** 0.45 heuristic / 0.55 ML (`predict_email` on sender + subject + body).
- **Limitations:** one public email distribution — marketing-style ham and non-English phishing under-represented.

### 2. URL malicious — `url_xgb_v2.pkl` (active) / `url_xgb.pkl` (v1 fallback)

- **Status:** active — `ml/models/calibration.json` key `url_model_version: "v2"`. When missing or on error, seamlessly falls back to v1 `url_xgb.pkl`.
- **Algorithm:** XGBoost over 15 features (`extract_url_features`):
  - Base 8 handcrafted features: length, Shannon entropy, digit ratio, has_ip, has_at_symbol, suspicious TLD, http-only, subdomain count.
  - Reputation feature: `domain_in_top1m` (0.0/1.0 via Cisco Umbrella Top-1M registrable domain lookup).
  - Path shape classification: `path_shape_cat` (0..4), `is_uuid_like`, `is_hex32_like`, `is_short_id`, `is_homepage`, `is_other`.
- **Dataset:** 800 base URL rows (400 URLhaus malicious / 400 Umbrella homepages) augmented with **3,000 synthetic benign deep-links** (`ml/augment_urls.py`) combining sampled Umbrella top-1M domains with path templates (`/c/<uuid>`, `/d/<hex32>`, `/watch?v=<id>`, `/share/<token>`, `/p/<hex16>`, `/file/d/<id>/view`). Total training set: **3,800 rows**.
- **Training metrics (v2):** accuracy 0.9950, precision 1.0000, recall 0.9900, F1 0.9950.
- **Blending:** 0.45 heuristic / 0.55 ML (`predict_url`).
- **Heuristic Reputation Adjustment:** When `domain_in_top1m` is True, `random_path_segment`, `url_entropy`, and `excessive_digits` are downgraded from `medium` to `low` with explanatory context citing high-reputation domain link structure. Critical indicators (`ip_host`, `brand_in_subdomain`, `suspicious_tld`, `urlhaus_pattern`) are never downgraded.

### 3. Deepfake v2 (single neural artifact) — `deepfake_cnn_v2.pt`

- **Status:** active — `ml/models/calibration.json` key `deepfake_model_version: "v2"`. This is the **only** neural deepfake artifact: the old 32×32 CIFAKE CNN (`deepfake_cnn.pt`) was deleted along with its loader branch. If the selected artifact is missing, detection degrades to **heuristics-only** (ELA splice + metadata) with an explicit `ml_model` indicator valued `heuristics-only-fallback` and a logged warning — there is no neural fallback.
- **Purpose:** eliminate false positives on genuine camera and messenger JPEGs (WhatsApp/Telegram re-encode every photo: downscale, JPEG q70-85, EXIF strip) while keeping recall on AI-generated images.
- **Architecture:** torchvision **MobileNetV3-Small** with ImageNet-pretrained weights (full fine-tune), classifier head replaced with a binary head (real=0 / fake=1), input **128×128**, ImageNet mean/std normalization (`ml/train_deepfake_v2.py`).
- **Datasets** (see [`docs/datasets.md`](datasets.md) §4): real = GenImage real/ImageNet subset (4,790) + `real_messenger` (10,000 messenger-degraded reals built by `ml/degrade_messenger.py`: longest side ≤ 1600 px, JPEG q70-85, EXIF stripped, optional mild sharpening); fake = GenImage StableDiffusion v1.4 (3,474) + Midjourney (1,360). Class-weighted CrossEntropyLoss (weights 0.6635 / 2.0295).

#### CNN vs ELA Disagreement Decision Matrix

To prevent ELA false-positives on high-texture or high-contrast genuine photos (e.g. `erew.jpeg`) while preserving sensitivity to localized tamper splices, `deepfake_detector.py` enforces the following calibration policy:

| Neural CNN Probability (`cnn_prob`) | ELA Splice Score (`splice_score`) | Policy Action | Effective Manipulation Cap | Max Risk Score & Severity | Indicator Representation |
|---|---|---|---|---|---|
| `< 0.10` (`cnn_real_threshold`) | `< 4.0` (`strong_splice_threshold`) | Overrule unconfirmed ELA residual | `weak_splice_manipulation_cap` (`0.35`) | `risk_score <= 40` (Safe or Low) | `high_block_variance` renamed to `ela_weak_splice_unconfirmed` (Low: "localized ELA residual not confirmed by neural model; monitor only") |
| `< 0.10` (`cnn_real_threshold`) | `splice_score >= 4.0` | Preserve localized tamper splice | Heuristic weight | `>= 41` (Medium or High) | `high_block_variance` retained with explicit override description citing strong localized residual |
| `< 0.10` (`cnn_real_threshold`) | No splice (`splice_score < 3.0`) | Genuine photo confirmation | `manipulation_cap_without_splice` (`0.35`) | `risk_score <= 40` (Safe or Low) | Standard metadata indicators (`missing_exif`, `global_recompression`) |
| `>= 0.10` (uncertain or fake) | Any | Standard monotonic 50/50 blend | Uncapped | Blended `max(ela, 0.5*ela + 0.5*cnn)` | Standard `ml_model` indicator + ELA indicators |
| Degraded (no model) | Any | Fallback to heuristics-only | Heuristic probability | Heuristic score | `heuristics-only-fallback` |
- **Augmentation (compression invariance):** JPEG quality jitter 60–95, resize jitter ±15%, random horizontal flip, brightness/contrast jitter; EXIF always absent.
- **Training on this machine (CPU-only, 12 cores, torch 2.14):**
  - `--quick` (64 px, 3 epochs, 20k samples, frozen backbone, cached decode): **0m51s wall-clock** — well under the 15-minute CPU target.
  - Full run (128 px, 10 epochs, early stopping patience 3 on validation F1 — never triggered): **18m03s wall-clock**, best validation F1 (fake class) **0.9052**. Decoded tensors cached as `.pt` shards under `ml/cache/deepfake_v2/`; DataLoader `num_workers=4`, `pin_memory`; CUDA AMP engages automatically when a GPU is present.
- **Evaluation gates** (held-out 10% split, threshold 0.5; tables in `evidence/reports/evaluation.md` + `ml/models/deepfake_v2_metrics.json`):
  - **FPR — real_clean 0.0376** (n=479) · **real_messenger 0.0220** (n=1000) · real_camera n/a (no contributed files yet) — both messenger/camera targets **< 0.05 ✓**; the WhatsApp-encoded genuine photo (`evidence/media/real_camera_whatsapp.jpg`) is predicted real.
  - **Per-generator recall — StableDiffusion 0.9193** (n=347) · **Midjourney 0.7426** (n=136).
- **End-to-end detector result** (ELA 50/50 monotonic blend): WhatsApp sample risk 10 (**safe**); `evidence/media/manipulated.png` risk 79 (**high**).
- **Limitations:** Midjourney recall (0.74) trails Stable Diffusion — the fetched MJ subset is smaller (1,360 images); the real_camera gate has no contributed photos yet, so camera evidence rests on the messenger subclass plus the single WhatsApp sample; synthetic Pillow splices (the manipulated.png regression sample) are out-of-distribution for the CNN and are caught mainly by the ELA blend.

### 4. Audio anti-spoofing v1 (LCNN) — `audio_cnn_v1.pt`

- **Status:** active — `ml/models/calibration.json` key `audio_model_version: "v1"` (values `v1` or `simulated`; missing file or unknown value → `simulated`, the pre-model deterministic hash score). When v1 is selected but the artifact is missing, audio analysis falls back to the simulated hash path with `simulated: true` and the reserved-model-hook indicator, exactly as before the model existed.
- **Architecture** (`ml/audio_model.py`, trained by `ml/train_audio_v1.py`): LCNN-style CNN over 80-bin log-Mel spectrograms of 3-second 16 kHz crops — five `[Conv2d → Max-Feature-Map → MaxPool]` blocks → BatchNorm2d → global mean+std pooling → 128-dim — **fused before the classification head** with a 6-dim handcrafted branch (spectral flatness, spectral-centroid std, HF rolloff, silence ratio, F0 std via autocorrelation, frame-energy kurtosis) through a 32-dim MLP. Single logit, class-weighted `BCEWithLogitsLoss` (pos_weight 0.6537), Adam, early stopping patience 3 on LA-dev F1, CUDA AMP when a GPU is present. The artifact embeds the handcrafted-feature mean/std scaler so train/serve standardisation is identical.
- **Features** (`ml/audio_features.py`, shared verbatim by training and inference): any container decoded via soundfile → torchaudio → ffmpeg CLI, resampled 16 kHz mono; 3 s crops with 50% overlap (pad or trim); light SpecAugment masking during training.
- **Datasets** (see [`docs/datasets.md`](datasets.md) §6): ASVspoof 2019 Logical Access train (bona fide + spoof attacks A01–A06 — LA train/dev contain only these six *seen* attacks; A07–A19 are the unseen eval attacks) for training, LA dev for early stopping/dev metrics — fetched from the HuggingFace parquet mirror of the official asvspoof.org/datashare.ed.ac.uk release because the official mirror throttles to ~180 KB/s (7.6 GB zip ≈ 12 h). Optional `--augment-piper` flag synthesises modern VITS TTS fakes offline (piper-tts) from 200 public-domain sentences; a WaveFake mirror and local espeak-ng synthesis form the fallback chain.
- **Inference** (`get_audio_model()`/`predict_audio()` in `app/services/ml_inference.py`): decode 16 kHz → score every 3 s crop → average crop probabilities for context, **flag on the max crop probability**.
- **Detector blending** (`deepfake_detector.analyze_media`, audio branch): when the model loads, `simulated` becomes false (UI badge: real forensic analysis) and an `ml_model` indicator valued `audio_cnn_v1.pt` carries the max-crop probability. Manipulation = **0.6 · model_prob + 0.4 · WAV heuristics** for WAV inputs, model_prob alone for non-WAV, always clamped by the monotonic `max()` against the heuristic probability. Without the model, the simulated hash path is byte-identical to the pre-model behaviour.
- **Explanation prompts** receive the model probability plus an explicit audio domain-shift caveat so narratives never overclaim on modern codec TTS (ElevenLabs) — high-risk audio is always routed to human verification.
- **Quick-mode training cost:** `--quick` measured on this machine (CPU-only, torch 2.14): **11m43s wall-clock** (3 epochs, 10,559 train / 10,425 dev crops from 6,582 train / 6,550 dev utterances, ≤2 crops/utterance) — under the 20-minute CPU target; crop-feature extraction is one-time cached under `ml/cache/audio_v1/`.
- **Dev metrics** (LA dev crops, best epoch, threshold 0.5): **F1 (fake) 0.8517 · accuracy 0.8249 · AUC 0.9138** (`ml/models/audio_v1_metrics.json → dev_metrics`; epoch history: dev F1 0.03 → 0.85 → 0.66 — training overfits past epoch 2, which is why early stopping on dev F1 matters).
- **Real-world gate** (evaluation-only split, NEVER trained on; reported separately and honestly in `real_world_gate`):

| Set | n | Probability ≥ 0.5 (max crop) | Probability ≥ 0.5 (mean) |
|---|---|---|---|
| ElevenLabs fakes (`datasets/media/real_world_audio/fake/ercv.mp3`) | 1 | **recall 1.00** (max-crop prob 0.855) | recall 0.00 (mean 0.487) |
| Real speech (`evidence/media/real_speech.wav`, bona fide LA dev) | 1 | **FPR 0.00** (0.268) | FPR 0.00 |

  The user-voice-memo half of the real/ gate split is currently empty, so the real-speech FPR rests on the single bona fide fixture — the JSON records `n` so this is always visible. The mean-vs-max gap on `ercv.mp3` is exactly the "flag on the max crop" deployment rule doing its job.
- **End-to-end detector results** (live, via `scripts/verify_deployment.py`): `ercv.mp3` → risk 85 (**critical**, `simulated: false`, `ml_model audio_cnn_v1.pt`); `tone.wav` (synthetic tone, non-speech) → risk 40 (**low**); `real_speech.wav` → risk 18 (**safe**). The regression matrix additionally asserts these verdicts (`scripts/regression_api.py` audio gates).
- **Limitations — read before trusting a negative:** (1) **domain shift** — trained on ASVspoof 2019 LA attacks (TTS/vocoder waveform conversion); modern codec-based neural TTS such as ElevenLabs is out-of-distribution, so real-world recall is expected to trail the in-distribution dev F1 and every gate number must be read as an honest transfer estimate, not an upper bound; (2) LA is Logical Access (no channel noise) — replay/physical-access and telephone-band audio are unmodelled; (3) lossy re-encode (mp3/m4a) degrades log-Mel cues; (4) 3-second crops miss long-range prosody; (5) the gate split is tiny (a handful of user-contributed clips) — confidence intervals are wide. High-stakes audio should always be escalated to human verification.

### 5. Network anomaly — `network_xgb.pkl` + `network_scaler.pkl`

- **Algorithm:** scaler + XGBoost over the 4 KDD99 "SF" features (log-duration, label-encoded service, log-src_bytes, log-dst_bytes); the service LabelEncoder is re-derived at load time from `ml/data/raw_network.csv` (deterministic refit).
- **Dataset:** `sklearn.datasets.fetch_kddcup99(subset="SF")` — **73,237 flows** on disk; binary target (normal vs any attack); 80/20 split → **58,589 train / 14,648 held-out test**.
- **Training metrics:** accuracy 0.9995, precision 0.9952, recall 0.9936, F1 0.9944.
- **Detection metrics (evaluation report, hybrid, n=60):** accuracy 0.8333, precision 0.9167, recall 0.7333, **F1 0.8148** (heuristics-only F1: 0.8462). Mean 11.641 ms / P95 33.949 ms.
- **Blending:** 0.45 heuristic / 0.55 ML; each flow dict is mapped to the training features with documented constants (duration and response bytes are absent from the flow schema and use the log-floor constant ln(0.1); service is derived from the destination port, unknown ports → KDD's `other`).
- **Limitations:** ⚠️ **KDD99 is 1998 DARPA evaluation data** — decades-old traffic patterns that barely overlap modern flows; the documented-constant feature mapping is a lossy domain bridge. The hybrid blend here cost 2 false positives (FPR 0.0667) while detection latency rose ~600× vs heuristics-only.

**Account takeover has no trained model** — its hybrid row equals the heuristics-only row (n=60: accuracy 0.8667, precision 1.0, recall 0.7333, F1 0.8462). **Impersonation/message** has no trained model either; the message module's hybrid row (n=600: F1 0.6826 vs heuristics-only 0.6270) reflects the SMS-proxy evaluation described in [`docs/datasets.md`](datasets.md).

## Explainable AI: provider chain

`app/ai/llm_gateway.py` tries providers strictly in order and returns as soon as one succeeds:

| # | Provider | Timeout | Notes |
|---|----------|---------|-------|
| 1 | Groq | `GROQ_TIMEOUT_SECONDS` (default 20 s) | OpenAI-compatible `api.groq.com` endpoint, model `GROQ_MODEL` (default `qwen/qwen3.8-27b`); skipped instantly when `GROQ_API_KEY` is empty |
| 2 | OpenRouter | `OPENROUTER_TIMEOUT_SECONDS` (default 20 s) | strict-JSON instruction, model `OPENROUTER_MODEL` (default `openrouter/free`), app-identifying headers (`HTTP-Referer`, `X-Title: CYBERGUARD`) |
| 3 | rule_based | instant (< 5 ms) | template generated locally from the indicator context when both remote providers fail; never fails |

- **Circuit breakers:** each remote provider sits behind its own `AsyncCircuitBreaker` (`app/ai/async_circuit_breaker.py`; threshold 3 consecutive failures, 60 s recovery window, CLOSED/OPEN/HALF_OPEN states). While a breaker is OPEN the gateway logs `Circuit breaker OPEN for <provider>, skipping to fallback` and moves to the next provider **instantly**.
- **Provenance:** every analysis response carries `explanation_provider` (`openrouter` | `groq` | `rule_based` | `cache:<original_provider>`) and `explanation_latency_ms`. Each provider failure logs one warning line: `LLM provider <name> failed after <ms> ms: <reason>`.
- **Strict JSON contract & Explanation Consistency:** per-module system prompts (`app/ai/prompt_templates.py`) constrain the model to `{"explanation": <paragraph starting with the assessed risk level>, "mitre_techniques": [{"id", "name"}], "recommended_actions": [<action strings>]}`. The final risk score and severity band are injected into the prompt, mandating that the first sentence starts with `<Band> Risk:`. `app/ai/llm_gateway.py` validates the leading band token; on mismatch, it retries once with a correction note; if still mismatched, it server-side replaces the leading band token to ensure 100% narrative consistency across all six modules and the SOC assistant.
- **Impersonation Weighting Calibration:** `authority_identity` carries LOW weight when detected alone. It escalates to HIGH only when combined with request-type indicators (`payment_request`, `status_confirmation`, `urgency`, `secrecy`, `channel_change`). Benign operational communications (e.g. vendor payment status confirmations from CFO/executives) are guaranteed to score $\le$ MEDIUM.
- **Cache:** successful explanations are cached in-memory for 3600 s (max 256 entries, thread-safe LRU) keyed by sha256 of module name + normalized input (media: sha256 of the file bytes). Hits return `explanation_provider = "cache:<original_provider>"` with zero latency.
- **Worst-case latency bound:** 20 s (Groq) + 60 s (OpenRouter) + < 1 s (rule_based) per analysis while providers are healthy; typically far less, zero on cache hits, and near-zero once a breaker has tripped. Detection heuristics, ML models, scoring bands and route signatures are unaffected — only the explanation source changes.
